About

This site records how the Solution Designer prototype is being designed with an AI assistant in the loop: every change is traceable to a question, the evidence gathered, the options mocked up and the decision taken.

Approach

The assistant does not decide. It gathers evidence, measures, proposes options with mock-ups rendered on the live prototype, states a recommendation and its trade-off, and then builds and verifies what the designer chooses. Each decision is logged with its reasoning so a reviewer can disagree with a specific step rather than with the result.

The loop used on every change: question from the designer, usually with an ECP screenshot · evidence from the QUIX library and from measuring both ECP and the prototype at the same scale · options rendered side by side · decision by the designer · verification in the browser.

Tools and sources

  • QUIX Design System, the Equinix design system: documentation and the Component Library v2 in Figma, read directly for sizes, colours and patterns.
  • Equinix Customer Portal, Fabric One and Marketplace pages, live and as the December 2026 Figma designs, used as the reference implementation.
  • Claude (Anthropic) working in Claude Code with the Figma MCP connector and a browser: reads specs from Figma, measures pages, renders mock-ups with headless Chrome, edits the prototype and verifies the result.
  • Prototype: a single-file React app styled with QUIX tokens, previewed locally.
